# VRMA 레이어 = 이산 제스처, idle 은 절차가 계속 소유

런타임: [anim/vrma/](../../../src/companion/anim/vrma/) — `clips.ts`(카탈로그) · `useVrmaLayer.ts`(재생·복귀 블렌드)

**새 동작 추가 = 파일을 `public/animations/` 에 떨구고 카탈로그 1줄.** euler 튜닝이 없고,
같은 파일이 남자1·여자1 양쪽에서 무수정으로 돈다(자동 리타게팅).
조달 경로·저작 방법·정적임 실측표는 [docs/vrma-adoption.md](../../../docs/vrma-adoption.md).

`AnimationMixer` 가 humanoid 본을 통째로 덮어쓰므로 그냥 멈추면 마지막 자세에서 **튄다**.
three.js `fadeOut` 도 답이 아니다 — 블렌드 상대가 액션 시작 시점의 **얼어붙은** 스냅샷이라
그 사이 움직인 절차 레이어와 어긋난다.

→ 매 프레임 **①절차 결과 스냅샷 → ②mixer 덮어쓰기 → ③가중치 w 로 스냅샷 쪽 slerp**
(w: 0→1→1→0, smootherstep). 상대가 **살아있는 절차 출력**이라 호흡 위상까지 맞춰 복귀한다.
w=0 이면 기존 동작과 동일(비퇴행).

## 불변식

- **소유권 이전 = 초기화 지점** — `action.stop()` 이 부르는 three.js `restoreOriginalState` 가 바인딩된 본 **전부**를 액션 시작 시점 값으로 되돌린다. ①절차가 **안 쓰는** 본(Hips·목·어깨·다리·손가락)은 복귀 목표를 제스처 직전 자세(rest0)로 둬서 restore 를 무효화(직전 출력으로 두면 목표가 자기 자신이라 VRMA 자세에 머물다 22° 점프) ②절차가 **쓰는** 본은 `stop()` **직후 최종 자세를 다시 써 넣어** 무효화 — 안 하면 그 한 프레임만 rest0 로 튀어 **손이 19cm 왕복하는 1프레임 블링크**가 화면에 나간다(R3F는 useFrame 다 돌고 렌더). 소유 판별은 "직전에 우리가 써 넣은 값 그대로인가"로 런타임에(채널 목록 복사 금지 — 한쪽만 바뀌면 조용히 어긋남)
- **클립 × 무드 합성 = 새 동작** ([clips.ts](../../../src/companion/anim/vrma/clips.ts) `VrmaClipDef.mood`/`moodAfter`): 파일을 새로 저작하지 않고 **본=VRMA / 표정=무드**를 겹쳐 만든다. 성립 근거는 공식 7종·wave.vrma 에 **expression 트랙이 없다**는 실측 — mixer 가 표정을 안 건드려 무드의 held 표정·일회성 눈웃음이 재생 중에도 산다. 레이어는 `companion:mood` 이벤트만 쏘고(표정 단일 소유는 무드 시스템), 종료·중단 시 `moodAfter`(기본 neutral)로 되돌린다. **무드는 본 블렌드보다 먼저** 걸어야 표정 ramp(400~600ms)가 팔 올라오는 동안 끝난다. 현재 예: `VRMA_GREET`(손인사+happy) = **컴패니언 진입 시 1회 자동**(`greetOnReady`)
  - ⚠️ 무드의 **루프 톤**(호흡·머리 템포)은 본이라 재생 중엔 안 보이고 복귀 후 반영된다
  - ⚠️ `npm run verify` 의 wave 프로브는 합성판이 아니라 **`VRMA_WAVE`(무드 없음)를 잰다** — 본 트랙이 같아 수치가 동일하고 표정이 안 섞여 회귀 감시가 깨끗하다. 합성 클립을 늘려도 프로브 대상은 바꾸지 말 것
- **부분 추출 금지** — 부위 마스킹/상대 모드/가중치 축소 전부 반려. VRMA는 전신 동시 운동 전제(실측: VRMA_02 의 hips 앞숙임 +19~30° 와 head 젖힘 −16~−25° 가 **짝**이라 하나만 가져오면 균형이 깨짐). 대신 **정적인 클립을 골라 전신 사용** + `hipsPosition` 트랙만 제거(고정 상반신 프레이밍 보호)
- **흔들기 축은 월드 기준** — 로컬 축은 자세 종속이라 예측 불가(실측: 손목 로컬 z=앞뒤 / x=좌우지만 폭 0.013 로 임계 미달 / 월드 z=좌우 0.082 통과). 저작 스크립트가 부모까지 월드 회전을 FK 누적해 변환 후 pre-multiply
- **정지 프레임으로는 depth 와 좌우를 구분 못 한다** — 필름스트립으로 고른 축이 프로브에서 앞뒤 흔들기로 판명된 적 있음. 손동작은 반드시 `npm run probe` 로 잰다(측정 창은 클립 타이밍에 맞출 것 — 창이 클립보다 길면 복귀 구간이 섞여 전부 깨진다). 검증 절차는 `motion-probe` 스킬
- **체형 차이는 리타게팅이 안 없앤다** — 자세는 맞춰주지만 팔 길이가 달라 이동폭은 다르게 나온다(같은 30°에서 남자1 0.131 / 여자1 0.096). **양 캐릭터 프로브 필수**
- **두 부위가 닿는 동작(박수 등)은 위험 등급이 다르다 — 런타임 최소 IK 로 푼다** — VRMA 는 **회전만** 담는데 접촉은 **위치 제약**이라, 소스 리그에서 맞던 손이 우리 캐릭터에선 어긋난다(같은 클립의 최접촉 손바닥 간격: 남자1 0.0227m / 여자1 0.0106m=겹침). 손인사에선 체형 차가 진폭 차(0.131/0.096)로 끝나 무해했지만 접촉 동작에선 보이는 결함이 된다
  - ❌ **에셋에 상수 오프셋을 굽는 해법은 반려** — ①벌어진 구간까지 왜곡돼 원본에서 멀어지고 ②**두 체형을 동시에 만족시키는 값이 아예 없다**(남자1 최적 0° / 여자1 최적 6°, 0·3·5·6·7·10 전부 측정). 벌릴수록 팔 긴 쪽이 더 열려 차이가 **커진다**
  - ✅ **`VrmaClipDef.minPalmGap` + [palmContact.ts](../../../src/companion/anim/vrma/palmContact.ts)**: 손바닥이 그보다 가까운 프레임에서만 양 상완을 월드 Y 로 바깥 회전시켜 되민다. 각도는 기하로 푼다(민감도 = (ŷ×d)·û → θ=need/민감도, **부호를 가정하지 않음**). 벌어진 구간은 안 건드리므로 **원본 리듬 보존**, 실제 기하를 재므로 **체형 무관**(보정 후 남자1 0.0226=원본 그대로 / 여자1 0.0210). 미지정이면 no-op
  - 판정은 `npm run probe -- --clap` (양손 모드, `probe.ts` `sampleClap`/`evaluateClap`). ⚠️ **접촉은 손목이 아니라 손바닥 중심(손목·검지밑·소지밑 평균)으로 잰다** — Hand 본 원점은 손바닥 안쪽이라 맞닿으면 손목끼리 거의 일치한다. 손목 거리로 재면 **손바닥이 6~8cm 뜬 허공 박수를 PASS 시킨다**(실제로 겪음). ⚠️ 손바닥 **정렬**은 접촉축 `(R−L)/|R−L|` 이 간격 0 근방에서 퇴화하므로(실측: 0.08 이상 0.76~0.86 / 0.04 미만 0.25, 130ms 만에 −0.58→+0.71 진동) **접근 구간에서만** 잰다
- ❌ **구간 반복(`repeat`)은 반려됐다** — 박수가 짧아 보여 한 주기 위상을 맞춰 2회 반복해 봤으나 **육안으로 매우 어색**했다(이음매를 맞춰도 모캡 한 구간의 되풀이는 기계적으로 읽힌다). 길이는 **트림 구간과 fade 시간**으로 조절할 것 — 클립이 짧으면 fade 를 줄여 full-weight 를 늘린다

## 새 동작 추가 절차

1. `.vrma` 를 `public/animations/` 에 둔다
2. `?vrma=1` 로 에디터를 열어 실험 패널에서 재생 → 프레이밍·관통을 눈으로 거른다
3. 쓸 만하면 **정적임**을 확인한다(전신 카메라 전제 모션은 프레임을 밀어낸다). 필요하면 개조 스크립트로 손본다([scripts/makeWaveVrma.mjs](../../../scripts/makeWaveVrma.mjs) 참조 — GLB 구조를 안 건드리고 회전 accessor 의 float 만 제자리 덮어써 결정적 재생성이 된다)
4. [clips.ts](../../../src/companion/anim/vrma/clips.ts) 카탈로그에 항목 추가(구간 트림 + 블렌드 시간)
5. `npm run probe` 로 수치 판정 — **양 캐릭터 모두**. 임계값은 건드리지 않는다
