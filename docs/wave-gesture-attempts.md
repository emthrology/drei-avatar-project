# 손인사(안녕 wave) 개발 경과 — 보류 (2026-07-08)

FK 단일 본 제어로 "자연스러운 손인사"를 만들려다 **실패, 보류**. 재시도 시 반복 삽질을 막기 위해
시도·실패 원인·재개 방향을 기록한다. 코드는 삭제 않고 **주석으로 감춰둠**(아래 "코드 위치").

## 목표

- 동작: 오른손 들어 좌우로 흔드는 "안녕" 인사 (첨부 참고 이미지 = 상완 거의 내림 + 팔꿈치 접어
  하완만 세우고 손 좌우로).
- 트리거(결정됨): **① 등장(ready) 시 1회** + **② DebugPanel 수동 버튼**. idle 랜덤·게임이벤트는 제외.

## 검증된 오른팔 축 (이번에 얻은 소득)

| 채널 | 의미 | 비고 |
|------|------|------|
| `armR.z` | 프론탈 들기/내리기 | rest +1.3(내림). ↓일수록 옆으로/위로 벌어짐 |
| `armR.x` | 앞뒤 스윙 | **음수=앞** |
| `armR.y` | 상완 롤(길이축) | 내린 팔에선 잘 안 보이나, **팔꿈치 접힘'면'을 결정**. 든 팔에선 스윙 보임 |
| `elbowR.z` | 팔꿈치 굽힘 | 우+. 값↑ = 하완 더 접힘(≈2.4에서 손이 어깨, 3.5는 과굴곡) |

## 시도 이력

1. **armR.z 스윕** (0.08↔0.48) → 든 팔이 **위아래 flap**. 좌우 흔들기 아님. ✗
2. **상완 수평 들기(armR.z 0.3) + armR.y 오실레이션** → 팔 전체가 **덜렁덜렁**. 사용자: 상완이 아니라
   하완이 올라와야. ✗
3. **하완 주도(armR.z~1.0, elbowR.z 강한 굽힘) + armR.y 흔들기** → 상완이 흔들려 거슬림. 사용자:
   elbowR.z가 실제 흔드는 부위, 상완 흔들림 최소화 요구. ✗
4. **elbowR.z 오실레이션(2.9↔3.5)로 흔들기, armR.y 제거** → **하완이 상완과 겹침**(접힘면이 정면이라
   포개짐). 사용자: 하완은 반드시 상완 '앞'에. ✗
5. **armR.y 상수 롤로 접힘면 앞으로** → (a) **팔꿈치가 뒤로** 접힘(부호 반대) + (b) 접힘면이 앞이 되니
   elbowR.z 흔들기가 **앞뒤**가 됨. 좌우 흔들기를 armR.y로 재이관 시도했으나 수렴 실패 → **보류**. ✗

## 실패의 근본 원인

- **커플링 지옥**: `armR.y`(상완 롤)가 *하완 앞뒤 배치*와 *elbow 흔들기 방향*을 동시에 지배 →
  "하완을 상완 앞에" + "손 좌우 흔들기" + "상완 정지"를 **단일 본 3개(z/x/y)+elbow로 동시 만족 불가**.
  한 조건을 맞추면 다른 조건이 깨지는 순환.
- **손목(Hand 본) 미사용**: 사람의 손인사 좌우 흔들기는 실제로 **손목 flick**이 주도한다. 이번엔
  상완/팔꿈치만 건드려서 부자연 + 커플링에 갇힘.
- euler XYZ 합성으로 축이 서로 간섭(회전 순서 의존).

## 재개 방향 (다음에 시도할 것)

1. **★손목(Hand) 본으로 흔들기** — 상완·팔꿈치로 "하완 앞·세움" 자세만 **정적** 확정하고, 좌우
   흔들기는 `RightHand` 본 회전 오실레이션으로. 팔은 고정, 손만 까딱 → 커플링 회피 + 자연스러움.
   (채널 `handR.*` 신설 + `channels.ts` apply에 본 매핑 추가 필요)
2. **IK 도입** — 손 목표점 고정 후 팔 자세 풀이. 과하지만 정밀. [ik-plan.md](ik-plan.md).
3. **authored 클립** — Blender에서 수작업 키프레임 → import. 절차 애니와 별개 경로.
4. **눈높이 타협** — 좌우 흔들기 포기하고 "손 들어 잠깐 유지"(정적 raise + 살짝 tilt)로 단순화.
