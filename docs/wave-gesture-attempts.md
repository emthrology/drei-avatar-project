# 손인사(안녕 wave) — 완료 (2026-08-04)

FK 5회 실패 후 보류했다가, **검증 방식을 바꿔** 재개해 완료. 양 캐릭터(남자1·여자1)에서
프로브 6개 지표 전부 통과.

새 손동작을 만들기 전에 [vrma-adoption.md](vrma-adoption.md)를 **먼저** 읽을 것 —
아래 방식(절차 FK 저작)의 구조적 비용이 이 문서 전체다.

## 무엇이 문제였고 무엇이 풀었나

5회 실패는 전부 **커플링**이었다. "하완을 상완 앞에 + 손 좌우로 + 상완은 정지"를
상완/팔꿈치 3축만으로 동시에 만족시킬 수 없었다 — 하나를 맞추면 다른 게 깨지는 순환.

푼 것은 **흔들기를 손목으로 이관**한 것. 그러자 `armR.y`(상완 롤)가 자세 전용으로 free 해져
접힘면 조정에 쓸 수 있게 됐고, 세 조건이 서로 다른 본에 분리됐다.

두 번째로 결정적이었던 것은 **육안 → 수치 검증 전환**([probe.ts](../src/companion/anim/probe.ts)).
"덜렁덜렁" 같은 표현으로는 수렴이 불가능했다.

## 최종 값 ([moods.ts](../src/companion/anim/moods.ts) `WAVE`)

| 축 | 값 | 역할 |
|---|---|---|
| `armR.z` | 1.25 | 상완 내림 — **벌리지 않는다**(외전은 손 높이 상관 0.07로 무효) |
| `armR.x` | −0.75 | 어깨 굴곡(앞으로) — 손 높이를 버는 실질 축 |
| `armR.y` | −0.8 | 어깨 외회전 — 하완이 몸통 안 스치고 바깥으로 |
| `elbowR.z` | 2.9 | 팔꿈치 굴곡 — 손 높이 지배(상관 0.86) |
| `elbowR.y` | −0.8 | 하완 스윙(**twist 아님** — 위치 축) |
| `elbowR.twist` | 1.8 | 회외 → 손바닥 정면(palmFwd 0.85~0.98) |
| `elbowR.x` | ±0.3 | 하완 흔들기(손목과 동위상) |
| `handR.y` | ±0.3 | 손목 흔들기 |

## 이번에 확정된 리그 사실 (재현 시 필수)

1. **손목 축→방향 매핑은 팔 자세에 종속.** 자세를 바꾸면 처음부터 다시 재야 한다. 추측 금지
2. **euler 커플링**: `armR.y`(롤)를 켜면 `armR.z`(들기)가 무력화된다(손 높이 상관 0.86→0.07)
3. **굴곡된 팔의 롤은 euler로 표현 불가** — `R=Rx·Ry·Rz`라 굴곡(z)이 안쪽에 먼저 적용되고
   x·y는 부모 고정축 기준. `elbow.x`/`elbow.y`는 롤이 아니라 하완을 **휘두른다**(실측: 손이
   허리↔목으로 이동) → `*.twist` 채널 신설([channels.ts](../src/companion/anim/channels.ts))
4. **손목만으론 흔들기가 부족**하다 — 몸통 idle 회전 노이즈에 묻혀 주축 판정이 런마다 뒤집힘.
   하완(`elbowR.x`)을 동위상으로 얹어야 안정(좌우:앞뒤 1.9배)
5. **캐릭터마다 값이 다르다** — 남자1 통과 값이 여자1에선 미달. `--char`로 양쪽 검증할 것

## 프로브가 놓쳤던 것 (측정기의 한계)

지표가 전부 통과해도 **인사로 안 보일 수** 있다. 실제로 한 번 났다 — 6개 지표를 만족하는데
"팔을 만세로 든" 자세여서 참고 이미지와 완전히 달랐다. 프로브는 "좌우로 흔드는가"는 재도
"인사처럼 보이는가"는 못 잰다.

→ **역할 분담**: 눈 = 자세가 맞는가(방향 교정) / 프로브 = 그 자세에서 값 굴릴 때 회귀 감시.
필름스트립은 [scripts/waveShots.mjs](../scripts/waveShots.mjs)로 뽑는다.

측정기 자체의 결함도 두 번 나왔다(둘 다 육안 대조로 발견):
- **손목 관절로 흔들기를 재고 있었다** — 손목 회전은 관절 원점을 못 움직인다(실측 0.002).
  손목 주도 인사는 **구조적으로 통과 불가**였다 → 측정 지점을 손끝으로 이동(임계 0.08은 유지)
- **`palmOut`(측면)만 최대화**했더니 손이 날로 서서 화면에서 안 보였다 → `palmFwd`(정면) 추가

## ⚠️ 임계값 조정 규율

**프로브는 임계를 자동 조정하지 않는다.** `WAVE_TARGETS`는 박힌 상수이고 `evaluateArm`은
그것과 비교해 합불만 낸다. 바꾸려면 사람이 손으로 고쳐야 하고, 그래서 "PASS가 안 뜨니 기준을
낮춘다"는 경로가 실재한다.

| | 근거 | 조치 |
|---|---|---|
| **정당** | 물리적으로 도달 불가능한 기준이었음 (예: 손목 주도 흔들기인데 손목 관절에서 이동폭을 잼 → 항상 0) | 고치고 **근거를 기록** |
| **부당** | 0.28이 나왔는데 안 떨어지니 0.3으로 올림 | ❌ 프로브 무력화 |

차이는 **"물리적으로 불가능해서"냐 "통과시키고 싶어서"냐**다. 앞은 측정기의 오류를 고치는 것이고,
뒤는 측정기를 끄는 것이다.

**사용자가 완화를 요구하더라도 자동으로 따르지 말고** 어느 쪽인지 구분해 제시한 뒤 판단을 받는다.
조정했으면 반드시 보고한다 — 조용히 바꾸는 것이 최악이다.

> 이번 작업에서 **6개 임계값은 하나도 바뀌지 않았다.** 바꾼 것은 측정 *지점*(손목→손끝, 승인받음)과
> 측정 *구간*(`--wait`로 팔 드는 전환 구간 제외 — 포함하면 어떤 손인사도 '상완 덜렁거림'으로
> 불합격이라 통과 불가)뿐이다.
